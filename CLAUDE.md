# Mirror V2 — инструкции для Claude Code

@AGENTS.md

## Проект

Mirror — сервис диагностики HR-бренда и независимый индекс культуры компании (mirror-com.ru).
Этот репозиторий — новая версия сайта. Отвечай пользователю **на русском**.

**Позиционирование V2:** первый **внешний срез** через сервис Mirror — бесплатно для каждой компании, которая хочет
сотрудничать. Дальше подключается эксперт и **внутренняя проверка** (документы, данные компании, интервью) — это
платная диагностика. Графики показывают просадки и подъёмы по внешней и внутренней стороне бренда.

**Дизайн:** не использовать цвета, логотип и картинки старого сайта. Референсы — только ориентир оформления; структура своя.
Светлая тема, белые карточки, много воздуха. **Источник дизайна — макет Figma «Elements» и прототип `prototype/home` (ADR-0002):** акцент `#7A2FD1`, шрифты Onest и JetBrains Mono, размеры из макета. Сайт на Next отдаёт разметку прототипа один в один (ADR-0008). Структура и тексты — `docs/ux/site-structure.md` (v2). Тексты — по правилам в агенте `mirror-content`.

**Два направления:** «Оценка HR-бренда и индекс культуры» — снаружи, `/hr-brand` (индекс культуры, слепые зоны, место в
отрасли, матрица); «Дашборд здоровья корпоративной культуры» — изнутри, `/culture-health` (индекс переживаемой культуры, разрыв
с культурным кодом, 10 метрик, группы от 5 человек). Название «Пульс культуры» не используем. Данные и тексты страниц — в `prototype/home/pages` и `src/content.js` прототипа,
названия направлений — `DIRECTION_NAMES` в `src/content/site.ts`. Цвета: внешнее — фиолетовый, внутреннее — `health-*` (бирюзовый).

**Не наша тема:** подбор персонала, расчёт текучести, калькуляторы стоимости найма. Такие тексты не добавлять.

## Источники

- `fbushkov/mirror.service` — старый сайт (Nuxt). **Только чтение**, ничего в нём не менять. Клонируется в `/home/user/mirror.service`. Это **действующий сайт** — его код и сервер не трогаем; вся новая работа только в MirrorV2. Пример отчёта для доработки — его `public/demo.html` (ADR-0007).
- Решения 2026-10-27: заявки — на почту; хостинг V2 — REG.RU, сервер ведёт пользователь (ADR-0006); личный кабинет отложен, клиенту — отчёт PDF; парсер отдаёт выгрузку файлом, отчёт формирует ИИ.
- Парсер VK / Дзен / hh.ru / Dreamjob **уже существует** отдельно — не писать новый, только интегрироваться с его данными.
- `docs/content/site-texts.md` — тексты старого сайта; `docs/content/legal/` — юридические документы.
- `docs/architecture/site.md` — **архитектура сайта и платформы**: этапы (сайт → заявки → админка → кабинет), зоны маршрутов, слои, данные, доступы.
- `docs/adr/` — архитектурные решения (ADR). Новое решение с последствиями — новый ADR, через `mirror-architect`.
- `docs/product/business-rules.md` — **бизнес-правила**: что Mirror продаёт и обещает. Единственное место для услуг, цен, сроков и обязательств.
- `docs/product/report-data.md` — **отчёт как данные** (ADR-0009): схема `src/lib/schemas/report.ts`, методика в коде `src/lib/report/methodology.ts`, образец `src/content/demo-report.ts`. Новые показатели отчёта — сначала в схему и тест.
- `docs/product/cabinet.md` — **проект личного кабинета**: роли, разделы, доступ по ролям и услугам, сотрудники без входа, сценарии, данные, первая версия.
- `prototype/cabinet` — **прототип личного кабинета**: один файл `dist/cabinet.html`, данные — демо-отчёт по схеме и словарь терминов (`tools/report-build.mjs`), стили сайта плюс `src/cabinet.css`. Размеры в кабинете — классические shadcn (кнопки 36, текст 14), не увеличенные размеры сайта. В Next не выгружается: образец для разработки на React. Сборка: `python3 prototype/cabinet/build.py`.
- `docs/architecture/agents.md` — архитектура будущих агентов внутри продукта (не путать с агентами разработки ниже).
- `prototype/home` — **источник дизайна и разметки всех страниц сайта** (ADR-0008) и дизайн-система (`design-system.html`). Правка вида или текста: правим прототип, затем `python3 prototype/home/build.py && python3 prototype/home/build.py --next` и коммитим выгрузку (`src/site`, `public/site`, `prototype/home/dist`).

## Стек и команды

Next.js 16 (App Router, `cacheComponents`), TypeScript. Страницы — разметка прототипа (`src/site`), стили — `src/site/styles.css`, графики — своя сборка ECharts (`prototype/home/vendor`, собирается из пакета `echarts`) в `public/site`. Radix и shadcn в зависимостях оставлены для форм и кабинета на React. Tailwind не используется.

```bash
npm run dev      # http://localhost:3000
npm run build    # обязательно перед коммитом
npm run lint
npm run typecheck   # tsc --noEmit
npm test            # Vitest, src/**/*.test.ts
npm run test:e2e    # Playwright по собранному сайту (после build), tests/e2e
npm run check       # check:text + lint + typecheck + test
npm run check:text  # символы и тексты: невидимые символы, эмодзи, NBSP символом, «→», штампы, дефис вместо тире (входит в check и CI)
```

CI (`.github/workflows/ci.yml`) гоняет всё это на каждый push. Тесты не отключать и не пропускать ради зелёного CI.

Соглашения:
- `src/site/pages/*`, `manifest.json`, `shell.json`, `styles.css` и `public/site/*` — выгрузка `build.py --next`, руками не править;
- страница прототипа — свой `src/app/<адрес>/page.tsx` с `<SitePage name>` и `siteMetadata()`; страницы на React (документы, 404) — в `SiteShell`, текст через `typograf()`, `main` с `data-no-typograf`;
- ссылки — обычные `<a>`, не `Link`: скрипты страниц прототипа запускаются при полной загрузке;
- цвета — только переменные из `prototype/home/src/styles.css` (снаружи — фиолетовый, изнутри — бирюзовый);
- `new Date()` и прочие нестабильные значения в серверных компонентах ломают prerender (`cacheComponents`);
- новая страница — запись в `ROUTES` (`src/content/site.ts`): из неё sitemap и смоук-тесты;
- короткие слова (1–3 символа) не остаются в конце строки — `typograf()` из `src/lib/typograf.ts` (правило пользователя);
- серверный код (с этапа заявок) — в `src/server/*`, схемы Zod — в `src/lib/schemas`; см. `docs/architecture/site.md`.

## Агенты разработки (`.claude/agents/`)

Основная сессия — **маршрутизатор и оркестратор**: разбирает задачу, отдаёт части профильным агентам, собирает
результат, проверяет и коммитит. Сама крупную профильную работу не делает, если есть подходящий агент.

| Задача | Агент |
|---|---|
| Архитектура: маршруты, слои, модель данных, выбор библиотек, ADR, план крупной задачи | `mirror-architect` |
| Макет Figma → токены и компоненты, сверка с макетом, прототипы, дизайн-система | `mirror-design-system` |
| Страницы, вёрстка, адаптив (прототип и выгрузка в Next), страницы на React | `mirror-frontend` |
| Графики и дашборды ECharts | `mirror-charts` |
| Тексты сайта, тон, позиционирование, типографика | `mirror-content` |
| Методика индекса, демо-данные, проверка цифр, данные парсера | `mirror-analyst` |
| API, форма заявки, БД, интеграция с парсером, почта | `mirror-backend` |
| Кабинет клиента `/app`, админка `/admin`, вход, роли, изоляция данных | `mirror-access` |
| SEO, metadata, sitemap, редиректы, Яндекс Метрика, скорость | `mirror-seo` |
| Написать тесты: Vitest, Playwright | `mirror-tests` |
| Проверка: сборка, линтер, скриншоты, консоль, мобильная версия | `mirror-qa` |
| Ревью диффа перед коммитом | `mirror-reviewer` |
| Безопасность, 152-ФЗ, секреты, зависимости | `mirror-security` |
| Docker, деплой, CI, превью-артефакт | `mirror-devops` |
| Сообщения коммитов, CHANGELOG, описание PR, «что поменялось» | `mirror-release` |
| Обновить память проекта, сделать снапшот | `mirror-context-keeper` |

Типовые цепочки (независимые части — параллельно):
- **Новая страница:** design-system (если нет макета) → content → frontend + charts → tests → qa → reviewer → seo → release → context-keeper.
- **Перенос по макету:** design-system (токены, ui) → frontend → qa (сверка со скриншотами прототипа) → reviewer.
- **Форма, API, данные:** architect (ADR) → backend → tests → security → reviewer → release.
- **Кабинет, админка, доступы:** architect → access + backend + frontend → tests (изоляция, роли) → security → reviewer.
- **Баг:** tests (падающий тест) → профильный агент → qa.

Мелкие правки основная сессия делает сама; агенты — для профильной работы, где их правила важны.

## Память и контекст

- `.claude/memory/project-state.md` — **текущее состояние проекта** (сделано / в работе / дальше / открытые вопросы).
- `.claude/memory/decisions.md` — журнал решений (что решили, почему, кто).
- `.claude/memory/snapshots/` — автоматические снапшоты сессий (не в git).
- `.claude/logs/*.jsonl` — JSON-логи действий агентов (не в git).

Хуки делают это автоматически: при старте и после сжатия контекста подгружают состояние и последний снапшот,
перед сжатием и каждые N шагов сохраняют снапшот, каждое действие пишут в лог.

**Правило:** после завершения заметной задачи (новая страница, решение пользователя, смена плана) — вызвать
`mirror-context-keeper`, чтобы обновить `project-state.md` и `decisions.md`, и закоммитить их вместе с работой.
История изменений — `CHANGELOG.md` (`mirror-release`), архитектурные решения — `docs/adr/` (`mirror-architect`).
Снапшоты в облачной сессии живут только до её закрытия; переживает сессию только то, что закоммичено.
