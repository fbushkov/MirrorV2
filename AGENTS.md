# Mirror V2 — инструкция для любого ИИ

Общая память проекта: что сделано, как и почему, в каком порядке читать и по каким правилам работать.
Подходит для любого ассистента (Claude, Cursor, Codex и других). Своё для Claude Code — в `CLAUDE.md`.
С пользователем и в документах — **на русском**.

## Проект

Mirror — сервис диагностики HR-бренда и независимый индекс культуры компании (mirror-com.ru). Этот репозиторий — новая версия
сайта и платформы (MirrorV2). Первый **внешний срез бесплатный**, дальше эксперт и платная **проверка изнутри**.
Два направления, которые не смешиваются в одну цифру: «Оценка HR-бренда и индекс культуры» — снаружи, фиолетовый, `/hr-brand`;
«Дашборд здоровья корпоративной культуры» — изнутри, бирюзовый, `/culture-health`.

**Сделано:** сайт на Next.js отдаёт разметку прототипа; схема отчёта и методика в коде с тестами; проект и кликабельный прототип
личного кабинета; описание админки; бизнес-правила. **Не сделано:** форма заявки не отправляет данные, сервера и деплоя нет,
кабинет и админка не написаны (только прототип и документы). Подробно — `.claude/memory/project-state.md`.

## Порядок чтения

1. Этот файл целиком.
2. `.claude/memory/project-state.md` — состояние: сделано, в работе, дальше, ссылки на опубликованные прототипы.
3. `docs/product/business-rules.md` — что Mirror продаёт и обещает: услуги, цены, сроки, обязательства, эксперт.
4. Карта решений ниже — по теме задачи открыть указанный документ и ADR.
5. `docs/backlog.md` — открытые вопросы: не принимать за решённое то, что там открыто.
6. `.claude/memory/decisions.md` — журнал решений, новые сверху: кто и почему решил.
7. Перед кодом на Next.js — руководство в `node_modules/next/dist/docs/` (блок в конце файла).

## Где что лежит

- `prototype/home` — источник дизайна и разметки всех страниц сайта. Правка: прототип, затем
  `python3 prototype/home/build.py && python3 prototype/home/build.py --next`; коммитить выгрузку (`src/site`, `public/site`, `prototype/home/dist`).
- `prototype/cabinet` — прототип кабинета, сборка `python3 prototype/cabinet/build.py`, данные `node prototype/cabinet/tools/report-build.mjs`.
- `docs/product/` — продукт: бизнес-правила, кабинет, админка, отчёт. `docs/adr/` — архитектурные решения, список в `README.md`.
- `docs/architecture/site.md` — этапы, маршруты, слои, данные, доступы. `docs/architecture/agents.md` — будущие ИИ-агенты внутри продукта.
- `docs/ux/site-structure.md` — структура сайта; `docs/content/` — тексты старого сайта и юридические документы.
- `src/lib/schemas/` — схемы Zod; `src/lib/report/` — методика; `src/content/` — контент, демо-отчёт, словарь; `src/site/` — выгрузка прототипа.
- `fbushkov/mirror.service` — **старый действующий сайт, только чтение**: ничего не менять. Пример отчёта — его `public/demo.html`.
- Парсер VK, Дзен, hh.ru, Dreamjob **уже существует** отдельно: не писать новый, работать с его выгрузкой.

## Правила работы

**Тексты** (правила владельца):
- без стрелки «→», штампов ИИ, эмодзи; двоеточие только перед списком; без лишних тире; NBSP в коде — `\u00a0`;
- короткие слова (1–3 символа) не остаются в конце строки — `typograf()` из `src/lib/typograf.ts`;
- не использовать название «Пульс культуры»; не писать про подбор персонала, текучесть, калькуляторы стоимости найма;
- не удалять существующие блоки и тексты без вопроса владельцу.

**Цифры и данные:**
- цифры считает код по `methodology.ts`, ИИ пишет только тексты; новые показатели — сначала в схему и тест;
- группы меньше 5 ответивших не показывать никому; в отчётах нет имён авторов отзывов и сотрудников;
- один факт — одно место: бизнес-факты в `business-rules.md`, термины в `glossary.ts`; остальные документы ссылаются, не копируют;
- не выдавать предположение за решение: пометить «предложение» и внести вопрос в `docs/backlog.md`.

**Код:**
- `src/site/*` и `public/site/*` — выгрузка прототипа, руками не править; страница прототипа — свой `src/app/<адрес>/page.tsx`
  с `<SitePage name>` и `siteMetadata()`; страницы на React — в `SiteShell`, `main` с `data-no-typograf`;
- ссылки — обычные `<a>`, не `Link`: скрипты страниц прототипа запускаются при полной загрузке;
- цвета — только переменные из `prototype/home/src/styles.css`;
- `new Date()` и прочие нестабильные значения в серверных компонентах ломают prerender (`cacheComponents`);
- новая страница — запись в `ROUTES` (`src/content/site.ts`); серверный код — в `src/server/*`, схемы — в `src/lib/schemas`.

**Перед коммитом** — `npm run check` и `npm run build`; тесты не отключать ради зелёного CI. Коммиты по-русски, одна логическая
правка, работа в рабочей ветке; в `main` и в старый сайт не пушить.

**Решения записывать сразу, а не в конце:**
- журнал `.claude/memory/decisions.md` (что, почему, кто);
- ADR в `docs/adr/`, если решение меняет архитектуру;
- строка в карте решений выше;
- открытый вопрос — в `docs/backlog.md`, закрытый — убрать оттуда;
- `CHANGELOG.md` и `.claude/memory/project-state.md` — после заметной работы.

Переживает сессию только закоммиченное.

## Команды

```bash
npm run dev         # http://localhost:3000
npm run build       # обязательно перед коммитом
npm run check       # check:text + lint + typecheck + test
npm run check:text  # невидимые символы, эмодзи, NBSP символом, «→», штампы, дефис вместо тире
npm test            # Vitest, src/**/*.test.ts
npm run test:e2e    # Playwright по собранному сайту
python3 scripts/docs-html.py   # HTML-версии документов (pip install markdown)
```
