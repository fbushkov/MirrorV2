# Отчёт как данные

Схема: `src/lib/schemas/report.ts` (Zod). Методика в коде: `src/lib/report/methodology.ts`.
Образец: `src/content/demo-report.ts`, «Банк N», совпадает с демо-страницами сайта. Решение: ADR-0009.

Каждый отчёт Mirror сначала собирается как один JSON по этой схеме. PDF клиенту, PDF под брендом агентства и
будущий личный кабинет строятся из этого JSON, поэтому цифры везде одинаковые, а история замеров сохраняется с первого отчёта.

## Какие отчёты описывает схема

| `kind` | Услуга | Обязательные блоки |
|---|---|---|
| `external_scan` | Внешний срез, бесплатно | `external` |
| `external_monitoring` | Мониторинг, раз в месяц | `external` |
| `internal_diagnostics` | Диагностика, первый замер изнутри | `internal` |
| `internal_wave` | Замер внутри кампании | `internal` |
| `campaign_final` | Итоговый отчёт кампании | `internal`, `external` по желанию |

Если у клиента подключены оба направления, в отчёт добавляется `bridge`: сверка тем снаружи и изнутри.

## Структура

```
report
├── шапка: schemaVersion, methodologyVersion, id, kind, status (draft → review → published), demo,
│          company (название, отрасль, регион, численность), period (месяцы), preparedAt,
│          branding (mirror или агентство с логотипом)
├── summary          выводы: работает / риск / с чего начать
├── external         снаружи: оценка HR-бренда
│   ├── coverage       источники, число упоминаний, период
│   ├── index          индекс культуры, изменение, ряд по месяцам с событиями и просадками
│   ├── promises       обещания: где обещано, вес, упоминания, % подтверждения, статус, по источникам, цитаты
│   ├── blindSpots     слепые зоны: тема, доля упоминаний, тон, цитата
│   ├── industry       место в отрасли: группа сравнения, число компаний, перцентиль, перцентили по темам
│   ├── competitors    конкуренты: индекс, место в отрасли, статусы тех же обещаний
│   └── signals        мониторинг: резкий рост темы
├── internal         изнутри: здоровье корпоративной культуры
│   ├── waves          замеры: даты, приглашено, ответили (без ответов отдельных людей)
│   ├── delayDays      задержка публикации
│   ├── units          подразделения: дерево и численность
│   ├── index          индекс переживаемой культуры, зона, изменение за 30 дней, ряд
│   ├── metrics        10 метрик: балл, зона, изменение, уверенность, ряд, причины с уровнем доказанности, вклад каналов
│   ├── slices         срезы: метрика × подразделение × этап × период, размер группы, балл или скрыто
│   ├── code           нормы культурного кода: связанные метрики, балл, зона
│   ├── discrepancies  расхождения между каналами
│   ├── alerts         резкие изменения: метрика, на сколько, за сколько дней, где, контекст
│   ├── signals        лента обезличенных цитат: метрика, тон, канал, месяц
│   ├── confirming     подтверждающие сигналы (уровень 2), баллом не становятся
│   ├── context        события (уровень 3): смены руководителей, реорганизации
│   └── decisions      решения по обратной связи и что изменилось, флаг публикации для сотрудников
├── bridge           снаружи и изнутри: слепая зона или обещание против метрики, вид связи, вывод
├── plan             шаги: что, зачем, роль ответственного, срок, горизонт, эффект и затраты, показатель, статус
├── kpis             метрики успеха: сейчас, цель на 6 и 12 месяцев
├── dataGaps         чего не хватает в данных и где дособрать
└── extended         развёрнутый отчёт (разделы «Экспресс-аудита»): позиционирование, восприятие по аспектам,
                     вакансии hh.ru, соцсети, портреты аудитории, обзор конкурентов, контент-план, SWOT
```

## Что схема проверяет сама

Неверный отчёт не проходит разбор, и ошибка называет поле. Проверки повторяют методику со страниц «Как считаем».

- Статус обещания соответствует доле подтверждений: от 60% подтверждается, 40–59% частично, до 40% не подтверждается,
  меньше 10 упоминаний — нет данных.
- Веса обещаний в сумме дают 1, индекс культуры совпадает с расчётом по обещаниям (допуск 1 балл).
- Перцентиль отрасли есть только при 30 и больше компаниях в базе отрасли.
- Зона каждой метрики и нормы кода соответствует баллу: в норме от 65, внимание 50–64, риск ниже 50.
- Индекс переживаемой культуры совпадает со средним по 10 метрикам, балл нормы — со средним по её метрикам.
- В срезе группы меньше 5 человек балла нет.
- Цитата принимается, только если проверена на узнаваемые детали (`checked: true`).
- У анонимного сигнала нет поля подразделения: лишнее поле отбрасывается при разборе.
- Отчёт снаружи содержит блок `external`, отчёт изнутри — `internal`, сверка — только при обоих.

## Чего в отчёте нет никогда

- Имён авторов отзывов, имён сотрудников и руководителей. Ответственный в плане — роль.
- Ответов отдельных людей и сообщений целиком вне ленты проверенных цитат.
- Срезов, где группа меньше 5 человек, и сочетаний фильтров, дающих такую группу.
  Защиту от вычитания групп (разность двух срезов) проверяет сервер при выборке, ADR-0004.

## Как хранить

1. **Отчёт — неизменяемая версия.** Каждая публикация — новая запись `report_versions` с JSON в `jsonb`, `schemaVersion`
   и хэшем. Исправление — новая версия, старая остаётся. PDF хранится рядом как файл и ссылается на версию.
2. **Исходные данные отдельно от отчёта.**
   - Снаружи: выгрузка парсера (файл) хранится как есть, с хэшем, и указывается в версии отчёта: по ней отчёт можно пересчитать.
   - Изнутри: сырые ответы и сообщения хранятся отдельно, с ограниченным доступом и сроком хранения по договору
     с клиентом (152-ФЗ). В отчёт и в кабинет попадают только агрегаты и проверенные цитаты.
3. **Ряды для кабинета.** Динамика между отчётами собирается из версий по `company.id` и месяцам.
   Когда отчётов станет много, ряды можно вынести в отдельную таблицу, не меняя схему отчёта.
4. **Демо-данные** помечены `demo: true` и никогда не смешиваются с данными клиентов.
5. **Версии схемы.** Новое необязательное поле — та же версия. Переименование или удаление поля — новая `schemaVersion`
   и функция миграции старых отчётов. Изменение порогов методики — новая `methodologyVersion`, старые отчёты не пересчитываются.

## Как отчёт появляется

```
выгрузка парсера ─┐
данные изнутри ───┼─▶ расчёт кодом (methodology.ts) ─▶ JSON по схеме ─▶ ИИ пишет выводы (summary, hint, plan)
культурный код ───┘                                            │
                                              проверка схемой ─▶ эксперт: review ─▶ published ─▶ PDF / кабинет
```

Числа считает код, ИИ только формулирует текстовые поля. Для генерации ИИ схема выгружается в JSON Schema (`z.toJSONSchema`).
