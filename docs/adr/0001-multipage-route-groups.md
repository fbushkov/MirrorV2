# 0001. Многостраничный сайт: route groups, карта маршрутов, общие блоки
- Статус: принято · Дата: 2026-10-27 · Кто: пользователь (сайт многостраничный), Claude (схема)

## Контекст
Сайт будет многостраничным, позже появятся кабинет клиента и админка. Ссылки на страницы встречаются в шапке, мега-меню,
мобильном меню, подвале, крошках и sitemap — при ручных `href` они расходятся.

## Решение
- Зоны маршрутов: `(site)` — маркетинг, `(cabinet)/app` — кабинет, `(admin)/admin` — админка; у каждой свой layout.
- Одна карта маршрутов `ROUTES` в `src/content/site.ts`; меню, подвал, крошки, sitemap и metadata строятся из неё.
- Страница = набор общих секций (`PageHero`, `Section`/`SectionHead`, `CardGrid`, `Steps`, `Pricing`, `Faq`, `RequestForm`)
  с данными из `src/content`. Блоки с выбором по направлению (шаги, тарифы, FAQ) принимают фильтр, а не копируются.
- Прототип `prototype/home` устроен так же (layout + partials + pages + ROUTES в build.py).

## Последствия
Новая страница — это файл `page.tsx` и запись в `ROUTES`. Перенос существующих страниц в `(site)` адреса не меняет.

## Альтернативы
Одна общая layout для всего — отклонено: кабинету и админке не нужны маркетинговые шапка и подвал.
