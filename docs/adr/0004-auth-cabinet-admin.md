# 0004. Вход, роли, изоляция клиентов
- Статус: предложено · Дата: 2026-10-27 · Кто: Claude, ждёт пользователя (нужен ли кабинет к первым продажам)

## Решение (предложено)
- Вход по одноразовой ссылке на почту: живёт 10–15 минут, в БД — хэш токена; ссылка открывает страницу с кнопкой «Войти»
  (вход по POST — почтовые сканеры не сжигают токен); лимит запросов на email; одинаковый ответ для существующих и несуществующих адресов.
- Сессия на сервере (можно отозвать), новый ID после входа, тайм-аут простоя; cookie `__Host-`, Secure, HttpOnly, SameSite=Lax.
- 2FA для `mirror_admin` — обязательна с этапа 3.
- Роли: `mirror_admin`, `mirror_expert`, `client_owner`, `client_viewer`; связь пользователь—компания через `memberships`.
- Каждый запрос к данным фильтруется по `company_id` из сессии на сервере. `proxy.ts` — только перенаправление на вход.
  Второй уровень — Postgres RLS. Тесты на подмену id чужой компании (IDOR) обязательны.
- Правило «группы от 5 человек» применяется в серверной выборке дашборда — ко всем срезам, выгрузкам и комментариям,
  включая защиту от вычитания (пересечение фильтров или разность двух групп не дают срез меньше 5).
- `audit_log` только на добавление; пишем изменения, просмотры и выгрузки ПДн.
